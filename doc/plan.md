## 项目目标

用 PI SDK、Node.js 和 TypeScript 构建一个可运行、可评测、可解释的 Agent 应用。项目是个人练手项目，优先级为：完整原型 > 求职展示 > 开源影响力 > 基础设施学习。不要求先找到真实用户或商业化部署。

第一项可交付成果是可承载已注册任务能力的本地 Agent 工作台，并以“带证据的 GitHub 仓库技术分析”作为首个完整能力：

> 输入公开 GitHub 仓库与分析目标，固定提交版本，生成可逐条追溯证据的报告，并展示执行过程。

GitHub 仓库分析是第一项已交付能力和 v0.1 的端到端验收案例，不限制工作台后续承载其他已注册能力。通用任务外壳与具体能力分层演进；v0.1 仍为单 Agent、单一已接入能力，不宣称可以执行任意任务。长期按需推进恢复、多 Agent、沙箱、记忆、RAG、Skills 和 MCP；是否实施某项能力，由当期任务和评测证据决定。只读版本不把文档里的启动命令描述成已经成功运行的结果。

## v0.1 交付范围

### 输入与仓库快照

- 公开 GitHub HTTPS 仓库 URL、可选 ref 和分析目标；不支持私有仓库或 GitHub 写入操作。
- 先把分支/标签/ref 解析为明确 SHA，再获取源码；缓存、报告和证据均绑定该 SHA。
- 仅从受控 GitHub 获取源码和公开元数据。GitHub Token 可选，只用于限额，不能进入事件或报告。
- 获取方式优先使用固定 SHA 的源码归档；如果实现选择浅克隆，必须同样控制下载、超时、子模块、LFS 和本地 Git 配置影响。
- 下载后验证所有路径；拒绝符号链接、路径逃逸、特殊文件和超限输入。不递归获取子模块，不执行 checkout 后脚本或仓库命令。
- 限额必须在流式下载和解包过程中生效，不允许先完整下载/解压再判断超限。
- 第一个真实样例使用小型仓库。中、大型样例在小样例闭环后加入。

### 分析、证据与产物

- 一个主 Agent，明确的只读工具白名单：目录/文件元信息、受限文件读取、文本检索和证据登记。
- 目标仓库中的 README、AGENTS.md、Skills 或其他说明均视为待分析数据，不能自动成为高优先级指令。
- 禁用目标仓库和个人 PI 目录的自动扩展、Skills、上下文与提示模板发现。
- 不向 Agent 提供 shell、写文件、任意网络工具；源码获取和产物写入由应用中的固定流程完成。
- 报告覆盖定位、架构、关键模块、入口、依赖、文档声明的启动/测试方式、限制、未知项和下一步建议。
- 每条事实结论绑定证据 ID，证据含路径、行号范围、SHA 和摘录；网页元数据另记 URL、访问时间和响应摘要。
- 区分事实、推断、未知。没有执行目标代码时，不允许声称“启动/测试已验证成功”。
- `report.json` 是结构化事实来源；校验后由确定性模板生成 `report.md`，避免两种报告内容漂移。
- 每次运行保存 `manifest.json` 和结构化事件日志。失败或取消保留已有日志与部分证据，不能冒充成功报告。
- schema、引用路径、行号、SHA 和必需字段未通过时，运行不能进入 completed；人工语义评测另行记录，不宣称机器已证明全部结论正确。

### Web 与执行过程

- Next.js 通用工作台页面：默认主界面提供通用 composer，普通自然语言提示可直接进入 PI Agent 对话，不要求先选能力；默认工具白名单为空。需要专门能力时，可在独立栏目浏览或通过 `@名称` 显式调用，并按该能力 schema 收集输入；服务端注册表校验能力 ID 和输入后分发到固定处理流程，不让模型自动选择未显式启用的能力。页面还包括运行记录、事件时间线、结构化产物查看、取消和重试。v0.1 只注册公开仓库分析，但布局与 API 不绑定其专有字段。
- Fastify 提供 REST/SSE；v0.1 只运行一个 Server 进程，Agent 执行逻辑与 API 逻辑分离。
- 对话消息、能力调用、事件和产物采用可版本化、类型化契约；每轮成功结果包含 Agent 回复文本，产物可选；能力逐个注册，能力未显式启用时不可用，不把通用提示词理解为授予任意工具权限。能力完成后，将简短摘要和受限的结构化结果写入同一对话上下文，附产物引用，供用户继续追问；不把完整大型产物或内部执行日志塞入上下文。
- 实施顺序已完成：合成仓库离线“证据→报告”闭环、公开仓库固定 SHA 分析、经授权的模型验证，再接入 API/Web 工作台；当前集成验收状态以 TASK-006 为准。
- 服务进程全局默认最多一个活动运行；忙碌时明确拒绝新提交，暂不建立任务队列。一个 conversationId 对应一个进程内 PI 会话，每次提交有独立 runId；网络重放通过幂等键复用同一运行，显式重试用新 runId 并关联原运行。
- v0.1 进程存活期间支持 SSE 断线重连和按事件 ID 补发；缓冲区有上限，缺失事件时明确告知重新获取状态。
- 对话列表、消息和 PI 会话上下文在进程内保留，支持多轮提示、切换对话和页面刷新后按 conversationId 恢复；服务重启后不承诺恢复。失败或取消的能力运行可保留运行记录/部分产物，但不作为成功结果写入后续对话上下文。

#### TASK-006 首页视觉提示（草图阶段）

首页采用克制、简洁的深色 AI 工作台风格：炭灰背景、约 220–250px 左侧导航、宽阔主工作区；品牌、带线性图标的导航和底部设置入口放在侧栏，顶部工具入口低调呈现。主区在可用空间内居中显示欢迎内容、简短说明、圆角通用输入框和轻量操作按钮，留白充足，边框与分隔线柔和，少量强调色用于选中状态。公开仓库分析不作为首页固定表单或主视觉入口；能力在“能力”栏目浏览，并可通过 `@名称` 调用。

字体和排版按草图确认的层级执行：全站统一使用 `Inter, "Noto Sans SC", "PingFang SC", "Microsoft YaHei", system-ui, sans-serif` 一类的中英文无衬线字体栈；用 CSS 变量集中定义字号。品牌约 14px，导航与辅助信息约 12–13px，正文和主要控件约 13–14px，欢迎标题约 18–22px（建议 20px），说明文字约 12–13px。保持统一行高和字重，正文不低于 12px；标题克制清晰，说明文字柔和但仍易读。窄屏下导航可收起，内容不得横向溢出。前端已按此方向实现；桌面与窄屏 fake 模式验收记录见 TASK-006，真实 socket 断线仍未端到端模拟。

### 通用运行预算初值

以下为可配置的初值，需用后续真实评测校准，不是已证明的性能承诺：

| 约束 | 初值 |
| --- | --- |
| 整次运行时长 | 180 秒 |
| 模型调用次数（含重试） | 8 |
| 工具调用次数 | 20 |
| 累计输入与输出 Token | 32,000 |
| 单次模型最大输出 Token | 2,000 |
| 在线评测估算成本上限 | ¥1.33/次（按 DeepSeek 峰时价保守估算；runtime 内部沿用美元协议字段） |
| 源码归档下载大小 / 解包总大小 | 20 MiB / 100 MiB |
| 文件数量 / 单文件读取大小 | 5,000 / 256 KiB |
| 取消后等待协作式退出 | 1 秒，超出则记录未及时停止并禁止新调用 |

公开仓库在线评测使用单独的执行上限：12 次模型调用、24 次工具调用、累计 200,000 tokens、每次最多输出 2,000 tokens、180 秒。累计 Token 上限按第三次运行观测到的 100,247 tokens 提高至约两倍，为剩余模型/工具步骤预留空间；累计用量在 provider 响应后核算，输入 Token 无可靠的请求前预算估算，因此它仍是软阈值，在途请求可能越界。人民币 ¥1.33 也是应用侧估算上限而非 DeepSeek 侧硬限额。

预算由应用执行，不只写在提示词里；当请求前可可靠估算剩余用量时，应在下一次调用前检查余额，并对在途调用设置取消信号。当前在线评测的累计 Token 与成本按 provider 返回的 usage 事后核算，故仍是软阈值；单个在途调用可能越过阈值，不能承诺费用绝不超限。未知价格的模型不得进入要求成本上限的在线评测。

### v0.1 验收

- 合成 fixture 和一个固定 SHA 的公开小仓库能从输入到最终报告，不需人工改状态。
- 单元/集成测试离线运行，覆盖正常、失败、错误参数、工具取消、预算耗尽、引用错误、路径逃逸和恶意上下文。
- 结构化产物 schema 合法；所有仓库证据路径/行号/SHA 有效，引用完整率达到 100%。
- 人工维护必答事实清单，事实召回率初始目标 ≥80%；同时评估证据是否支持结论、无证据断言和正确弃答。
- 发布样例中不得把未执行的启动/测试步骤标为已执行成功。
- 连续三次运行无未处理异常是冒烟条件，不是可靠性结论。在线多次运行报告各次得分、费用和差异。
- UI 按顺序展示结构化事件和最终产物，取消/超时/失败原因可见。
- 新环境能按根 README 启动；CI 验证固定工具链、锁文件和离线检查。

## 按需建立的架构

```text
apps/web                  Next.js 页面
apps/server               Fastify API、SSE 和进程内执行入口
packages/protocol         版本化事件、结果、证据和产物 schema
packages/agent-runtime    PI 会话与受控资源适配
packages/tools            仓库快照、读取、检索与证据登记
```

先建立实际参与闭环的模块。v0.2 再提取 `apps/worker` 和 `packages/storage`；评测初期放在任务指定的 `evals/`，有复用需求时再独立成包。不预建空框架，不提前加入外部队列、PostgreSQL 或插件市场。

API 接收输入，固定流程获取快照，Agent 通过受控工具采集证据，应用校验结构化报告并生成产物，SSE 将版本化事件交给 UI。PI 事件只是输入，不能将其结束事件直接等同于业务成功。

v0.2 将为普通提示词路径逐步增加受控实际操作能力：工具必须显式注册并按白名单启用，文件操作限制在每个对话隔离的工作区内。v0.2 不默认开放任意 Shell 或不可信代码执行；需要执行目标代码时仍按 v0.4 的容器隔离目标另行实现和验收。具体工具集合与隔离机制由对应任务卡确定。

### 恢复的明确语义

v0.2 阶段划分为：获取快照 → 收集证据 → 分析 → 校验 → 发布报告。只恢复到已经完成的安全阶段；未完成阶段允许重跑，不承诺恢复到某个生成 Token 或任意工具中间状态。

- 将业务检查点、PI 会话历史、SSE 事件日志分开管理。
- 每次重跑有 attempt 标识，沿用同一快照 SHA，记录新增模型费用。
- 任务认领与租约阻止两个 Worker 同时执行；产物发布应具备幂等保护。
- 浏览器重连与 Worker 重启恢复是不同能力，各自验收。
- 外部写入当前不存在；未来引入时另定预览、人工确认、幂等和审计边界。

## 评测与质量门槛

- 先维护项目自有合成 TypeScript fixture，再加入固定 SHA 的 `sindresorhus/slugify`。
- `honojs/hono` 与 `earendil-works/pi` 作为后续规模扩展样例，尚未固定 SHA，不列为已完成评测。
- 只保存第三方样例的版本、许可元数据和事实清单，不提交完整第三方仓库。
- 事实召回率 = 正确回答的必答事实数 / 适用必答事实总数；事实清单预先维护，不由待评模型临时生成。
- 引用有效率、证据支持率、无证据断言率、未知项处理分别报告；不能用路径有效率替代正确性。
- 对比“同一 PI 模型和工具直接运行”与项目受控工作流，固定数据集、SHA、提示版本和预算。
- 在线模型测试须按任务单独授权和运行，记录模型 ID、价格表版本、Token、时长、费用、失败与重试。TASK-005 已完成固定样本质量评测；TASK-006 已有用户反馈的普通对话与仓库分析在线冒烟记录。后续新增付费运行仍须单独授权。
- 负向测试证明错误确实失败；测试通过仅支持已覆盖场景，不代表生产安全或真实模型可靠性。
