# TASK-NNN：任务名称

## 元数据

- 状态：`backlog`
- 负责人：未分配
- 分支或 worktree：未创建
- 基线提交：实施开始时记录
- 依赖任务：填写
- 提交/推送授权：无
- 在线模型授权：无；默认离线

## 背景与目标

用一个可验证结果描述任务价值，引用计划版本和相关 ADR。

## 范围与非目标

列出本轮交付以及不能顺手实现的内容。

## 允许路径与依赖授权

- `path/to/owned-area/**`

明确共享文件唯一写入者。新增依赖、根锁文件或协议变更必须具体授权；没有授权不修改。初始化步骤可交用户执行，但需给出准确工作目录和命令。

## 输入与前置条件

列出已有代码、设计、依赖任务和必须先决定的问题。

## 验收标准

- [ ] 每项均有可以执行的检查或明确人工步骤。
- [ ] 预期失败确实失败，不吞异常或接受无关错误。
- [ ] 文档、任务索引与实际状态一致。

## 验证命令与证据

区分计划命令、已执行命令、结果与未验证项。尚不存在的命令注明“实施后提供”，不能写成已运行。

## 决策、冲突与范围变化

记录变化、原因、集成者决定及未完成问题。

## 交接

- 当前状态：未开始。
- 完成内容：无。
- 修改路径：无。
- 实际验证：无。
- 风险与未验证：填写。
- 提交 SHA / PR：无。
- 已停止写入：填写。
- 下一位 Agent 第一个动作：填写。

实现完成进入 review；只有验收、审查和集成都完成才进入 done。
